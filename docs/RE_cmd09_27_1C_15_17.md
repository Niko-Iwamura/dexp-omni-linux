# OMNI.exe (DEXP OMNI / Eevision) — USB HID protocol: commands 0x09 / 0x27 / 0x1C / 0x15 / 0x17
### Key-table writes (bank 0 / bank 2), keyboard control pulse, macro-table upload, "Shoot" rapid-fire upload — full RE report

Binary: `OMNI.exe` (PE32, image base 0x400000, `.text` VA 0x401000). All addresses are VAs.
Tools: `scripts/disas.py`, `scripts/agentA_fn.py` (function-start-aware disassembler), `scripts/agentA_callers.py` (E8 + abs-dword xref scanner), `scripts/agentA_str.py` (string dump + caller scan), `scripts/agentA_cmdmap.py` (command-byte extractor for all 0x47BD30 callers).
Companion report: `RE_cmd0A_0B_1A.md` (cmds 0x0A/0x0B/0x1A, key-remap pages) — its findings are cross-referenced below as [R2].

## 0. Shared frame & object model (recap, extended)

### 0.1 64-byte report frame (all five builders)
Built in stack buffer `[ebp-0x44]` (cmd 0x1C: `[ebp-0x44]`), response in `[ebp-0x84]`:

| off | meaning |
|-----|---------|
| 0 | `0x04` (report magic / class) |
| 1 | checksum low = `sum(buf[3..63]) & 0xFF` |
| 2 | checksum high |
| 3 | **command** |
| 4 | chunk length (bytes of payload in this packet) |
| 5 | offset low (LE16 offset of this chunk, see per-cmd semantics) |
| 6 | offset high |
| 7 | `0x00` |
| 8..63 | payload (memcpy'd before checksum) |

Transport: `0x47BD30` — thiscall `send_recv(this, req, 0x40, resp, 0x40, &rc)`; returns 1 on success (see [R2 §0]).
Response: `recv[7]` — `0xFF` → ret `-102` (0xFFFFFF9A), `0xFE` → ret `-103` (0xFFFFFF99).

### 0.2 Device ("comm") object — embedded at parent+0x87C
| field | meaning |
|-------|---------|
| `+0x00` | u16 **total transfer length** (`dev->word[0]`) — set by `0x47F440(dev, len)` (rejects len>0x200); used as loop bound by cmds 07/09 |
| `+0x14` | open/ready flag (`0x434450` returns it; callers gate on parent+0x890 == dev+0x14) |
| `+0x1C` / `+0x2F4` | HID interface 1 / 2 handles (known) |
| `+0x60C` | **lock object A** — `0x4788B0(dev+0x60C)` = `EnterCriticalSection(dev+0x614)`; release = indirect call `(*(*(dev+0x60C)))[+0x14]` with `this = dev+0x60C` |
| `+0x62C` | lock object B (used by cmd 0x0B, see [R2]) |
| `+0x64C` | transfer-mode flag (0 = 56-byte, 1 = 24-byte) |
| `+0x658` | u8 **chunk size**: 0x38 (56) normal, 0x18 (24) alternate interface |

### 0.3 Parent classes (RTTI-verified)
* Keyboard: **`CEevisionKeyboardDevice`** — ctor 0x492A10 (base ctor 0x4B7710 → DuiLib `CHorizontalLayoutUI` + `CNotifyPump`), **vtable 0x69AD20**.
* Mouse: **`CEevisionMouseDevice`** — **vtable 0x69B134**.
Both embed the comm object at `+0x87C`. Relevant parent fields:

| parent offset | meaning (evidence) |
|---------------|--------------------|
| `+0x890` | mirror of dev+0x14 (device open) |
| `+0xEC8` | device-class/feature flag ("is keyboard", [R2 §4.5]); gates the `cmd 0xAA` probe path |
| `+0x1534` | 34-byte **device-info block** cache (cmd 04 03, builder 0x47D080): `[0x1534]`=model id, `[0x1539]`=info[5]=**key/slot count** (e.g. 126; ≤170), `[0x153A]`=info[6]=**macro storage capacity in 128-byte units** (`max_table_size = info[6] << 7`) |
| `+0x1558`,`+0x1568`,`+0x156C`,`+0x1570` | notify/observer pointers, UI control cache ([R2]) |
| `+0x17A0` | dword: "special" slot index (skipped by group merge) |
| `+0x17C0` | array: **slot → app key index** (0xFF/0xAA = unmapped), 171 entries |
| `+0x17C8` | array: **app key index → slot** ([R2 §4.8]) |
| `+0x17D8` | array: per-group "leader" item indices (group merge, cmd 0x27 caller) |
| `+0x1788` | dword **device type**: 1 = keyboard, 2 = mouse (setter 0x4B8EC0 also sets +0x178C; getter 0x4B8EF0) |
| `+0x1834` | model id ([R2]) |
| `+0x1840` | current remap layer index ([R2]) |
| `+0x1842` | control-manager pointer (FindControl base, `0x4555A0`) |
| `+0x18F0` | broadcast **app-state flag** (setter 0x4B9EB0 fires cmd 0x1C); `+0x18F4` sibling flag (setter 0x4B9EF0) |
| `+0x1AA8` | container (id list used by profile/macro reindex) |
| `+0x1D10` | **512-byte table A**: 3 bytes/slot, read via **cmd 07** (init handshake 0x495040 / mouse 0x4A88xx), written via **cmd 09** (this report) |
| `+0x2710` | **512-byte table B**: 3 bytes/key, source of **cmd 0x27** (this report; no other keyboard-class writer found — see §2.3) |
| `+0x2910` | 512-byte table C: 1 byte/LED — read via **cmd 1B** ([R2]); written via cmd 0x12 (0x47E830) |
| `+0x2D10/0x2D90/0x2DA7/0x2DE8/0x2E40` | profile/settings blocks via cmd 05/06 (0x21-byte records, count byte at offset 0, 34-byte current block at `count*0x21`) |

### 0.4 3-byte key-record format (established by [R2 §5.2] against `DefaultData/Keyboard.json`)
`[T, X, P]`: `T`=type (`0x20` normal HID key, `0xA0` media/consumer, `0xD0 0xA2 0n` M1–M5 macro keys, …), `X`=modifier bitmask / code, `P`=HID usage / param. JSON `Assignment = (T<<16)|(X<<8)|P`.
**New from this report:** the cmd-0x09 caller additionally treats `T == 0x71` and `T == 0x70` as **macro-binding types** whose `X` byte is a *macro index* (re-indexed when a macro is deleted, see §1.4).

## 1. Command 0x09 — chunked WRITE of key table A (bank 0, "live" assignments) — builder 0x47D360

### 1.1 Signature (thiscall, `ret 8`)
```c
int write_keytable_bank0(void* this /*ecx = comm obj, parent+0x87C*/,
                         u8* src,        // [ebp+8]  source buffer (>= dev->word[0] bytes)
                         u32 page);      // [ebp+0xc] bank/page index — MUST be 0
```

### 1.2 Construction
```
0x47D379  buf[0]=0; memset(&buf[1],0,0x3F)
0x47D38D  if (page >= 1) return -201 (0xFFFFFF37);        // unsigned compare, page must be 0
0x47D39D  memset(buf,0,0x40)
0x47D3B5  buf[0] = 0x04
0x47D3C2  buf[3] = 0x09                                    ; COMMAND
0x47D3EB  buf[7] = 0
loop (off = 0; off < this->word[0]; off += this->byte[0x658]):     // len from dev->word[0]!
  0x47D474  chunk = min(this->byte[0x658], this->word[0] - off)    ; 56 or 24
  0x47D482  buf[4] = (u8)chunk
  0x47D486  addr = page*512 + off                                 ; page==0 → addr = off
  0x47D4A3  buf[5] = addr & 0xFF ; buf[6] = addr >> 8             ; LE16
  0x47D4E0  memcpy(&buf[8], src + off, chunk)                     ; 0x5FEC40
  checksum buf[3..63] → buf[1..2]
  0x47D561  0x4788B0(this+0x60C)                                  ; LOCK A
  0x47D582  rc = 0x47BD30(this, buf, 0x40, recv, 0x40, &n)
  0x47D5A8  unlock = (*(*(this+0x60C)))[0x14](this+0x60C)
  if (rc != 1) return rc
  if (recv[7]==0xFF) return -102 ; if (recv[7]==0xFE) return -103
return 1
```
**Wire (first chunk, 126 keys → len 378, chunk 56):**
`04 <cksumLE16> 09 38 00 00 00 <56 bytes>` then `04 <cksum> 09 38 38 00 00 <…>` … last chunk `len=378-56*6=42`.

### 1.3 Response
Only `recv[7]` status check. **No response payload is consumed** (pure write).

### 1.4 Callers (E8 xrefs)
| call site | containing function | class | behavior |
|-----------|---------------------|-------|----------|
| 0x496093 | 0x495B60 (vtable 0x69AD20, slot 165) | keyboard | "apply key assignments incl. macro bindings, bank 0" |
| 0x4A9951 / 0x4A99F0 | 0x4A91F0 (vtable 0x69B134, mouse) | mouse | same, mouse variant (12 keys, ID table 0x6959C8) |

Caller 0x495B60 in detail (keyboard):
```c
if (this->[0x890] == 0) return 0;                       // device not open
cmd_03_read_info(this+0x87C, this+0x1534);              // refresh key count [0x1539]
memcpy(localTbl[512], this+0x1D10, [0x1539]*3);         // start from device copy (bank 0)
nMacros = _wtoi(GetText("MacroInfo"));                  // macro count from UI
for (i = 0; i < 0x7F; i++) {                            // per key-slot list
    keyIdx = slot2key[i] (this+0x17C0); if (keyIdx == 0xFF) continue;
    item = argList[i];                                   // {u16 id; u8 cur[3] @+2; u8 alt[3] @+8;…}
    if (item[2]==0x71 || item[2]==0x70) {               // MACRO-binding type codes!
        if (item[3] /*macro index*/ >= nMacros)
            item[0..1]=item[6..7]; item[2..4]=item[8..10];   // stale binding → restore alt copy
        else {                                           // re-index against the Guid id list
            j = idList.find(item[3]);
            if (j >= 0) item[3] = j;                     // rebind to new macro index
            else { idList.remove(item[3]); item[3] = idList.size(); } // append at end
        }
    }
    localTbl[keyIdx*3+0..2] = item[2..4];               // (T,X,P) into table
}
if (dev open) cmd_01_begin(dev);                          // 0x47CA40
buf = malloc([0x1539]*3); memcpy(buf, localTbl, [0x1539]*3);
rc = cmd_09(dev, buf, page = [ebp+8]);                    // page arg of the virtual method (0)
free(buf); cmd_02_end(dev, 1);                            // 0x47CC50
```
So the table contains **per-slot `[T, X, P]` assignment records**, and type bytes `0x71/0x70` mark keys bound to a macro (byte X = macro index; the caller shifts indices when the macro list shrinks — the classic "macro deleted, re-bind keys" flow).

Mouse variant 0x4A91F0 additionally gates on `this->[0xEC8]` and `cmd_0xAA(dev)` (0x47F1E0) before doing the same send (two call sites = the two branches).

### 1.5 Semantics
**cmd 04 09 = "write key-assignment table, bank 0"** — the same 512-byte area that **cmd 04 07 reads** (init handshake reads it into parent+0x1D10 and matches slots against the static default-layout tables 0x693080 (keyboard, 171 keys) / 0x6959C8 (mouse, 12 keys) to build the key↔slot maps, 0x497570/0x4ABFE0). The `page` argument addresses `page*512 + off` but is hard-restricted to 0 (returns −201 otherwise) — a driver should implement the full `page*512` addressing anyway; the app never uses page > 0.
Distinct from cmd 0x0B ([R2]) which writes the *layer* pages (`layer*0x200+off`) of stored profiles — cmd 0x09 writes the **live/current** bank that the device actively uses (and that is mirrored back by cmd 07).

## 2. Command 0x27 — chunked WRITE of key table B (second bank) — builder 0x47D620

### 2.1 Signature (thiscall, `ret 8`) — byte-for-byte identical skeleton to 0x47D360
```c
int write_keytable_bank2(void* this, u8* src /*[ebp+8]*/, u32 page /*[ebp+0xc], must be 0*/);
```
Only differences from cmd 0x09:
```
0x47D682  buf[3] = 0x27        ; COMMAND
(everything else — page<1 check (-201), chunk=min(+0x658, …), buf[5..6]=LE16(page*512+off),
 memcpy(&buf[8],src+off,chunk), checksum, LOCK A 0x4788B0/+0x60C, send, unlock, recv[7] checks,
 loop bound = this->word[0]) — identical.
```

### 2.2 Response
`recv[7]` status only; no payload consumed.

### 2.3 Caller (single)
| call site | function | class |
|-----------|----------|-------|
| 0x496608 | 0x4961A0 (vtable 0x69AD20, slot 166) | keyboard |

0x4961A0 — "apply grouped key settings to bank 2":
```c
if (this->[0x890] == 0) return 0;
cmd_03_read_info(dev, this+0x1534);
memcpy(localTbl[512], this+0x2710, [0x1539]*3);        // table B (member, persists across calls)
for (i = 0; i < size(this+0x17C0); i++) {
    leaderIdx = this+0x17D8[grp];  keyIdx = slot2key[i];
    if (i == leaderIdx && i != this->[0x17A0]) {
        grp++;
        leader = argList[leaderIdx];
        if (RgbEquals(leader+6, leader))               // 0x4132C0: compares 3 bytes @+2 vs @+8
            leader[2..4] = localTbl[keyIdx*3..+2];     // table B is authoritative for group leaders
    } else {
        localTbl[keyIdx*3..+2] = argList[i][2..4];     // item is authoritative otherwise
    }
}
cmd_01_begin(dev); buf = malloc([0x1539]*3); memcpy(buf, localTbl, [0x1539]*3);
rc = cmd_0x27(dev, buf, page=[ebp+8]); free(buf); cmd_02_end(dev, 1);
```
Note: no code path stores the merged local table back to `+0x2710`, and **no other keyboard-class writer of `+0x2710` exists** (exhaustive scan of every `0x2710` displacement in `.text` — the many other hits belong to a different DuiLib class whose own `+0x2710` container is constructed in 0x457720, and the rest are the *constant* 10000 / stack-cookie inits). So table B starts zeroed on a fresh object; on the wire, group-leader slots carry the (stale) `+0x2710` bytes and all other slots carry fresh UI assignments.

### 2.4 Semantics
**cmd 04 27 = "write second 512-byte per-key table"** — same 3-byte `[T,X,P]`-style record format, same `page*512+off` addressing (page pinned 0), same chunking/locking as cmd 0x09, but a **different device-side bank** (selected purely by the command byte). Best inference: a secondary/alternate assignment bank (e.g. an "FN"/secondary layer or the per-key binding set used by the grouped-apply UI flow). Needs a device experiment (write a recognizable pattern via 04 27, then dump with 04 05 at candidate offsets) to pin the address; nothing in the app ever reads it back.

## 3. Command 0x1C — parameterless keyboard control pulse — builder 0x47CE70

### 3.1 Signature (thiscall, **no stack args** — plain `ret`)
```c
int ctrl_1C(void* this /*ecx = comm obj*/);
```

### 3.2 Construction — single packet, everything zero
```
0x47CE89  buf[0]=0; memset(&buf[1],0,0x3F)
0x47CEA5  buf[0] = 0x04
0x47CEB2  buf[3] = 0x1C        ; COMMAND
0x47CEDB  buf[7] = 0
0x47CF04  buf[4] = 0           ; via idx 1*4
0x47CF2D  buf[5] = 0           ; via idx 1*5
0x47CF56  buf[6] = 0           ; via idx 1*6
          (payload already zero)
          checksum buf[3..63] → buf[1..2] = 0x1C, 0x00
0x47CFD4  0x4788B0(this+0x60C)                         ; LOCK A
0x47CFF5  rc = 0x47BD30(this, buf, 0x40, recv, 0x40, &n)
0x47D01B  unlock (same indirect vcall)
recv[7] checks (-102 / -103); return 1
```
**Exact wire packet:** `04 1C 00 1C 00 00 00 00` + 56 × `00`.

### 3.3 Caller (single) & trigger chain
| call site | function |
|-----------|----------|
| 0x4B9EE4 | 0x4B9EB0 — property setter, invoked on **every** device-view object |

```c
// 0x4B9EB0:
this->[0x18F0] = arg;                              // broadcast state flag
if (this->[0x18F0] != 0 && this->[0x1788] == 1)    // flag ON and device type == KEYBOARD
    cmd_1C(this+0x87C);
```
0x4B9EB0 is fanned out by 0x461930, which iterates the main window's device-view containers (`+0x11EC`, `+0x11F8`, …) calling the setter on each, with the argument taken from the **main-window state at main+0x58C**. The fan-out is invoked from the main window's message handler (0x45B9F3, 0x45FD9B, 0x45FE15, 0x45FE37 — the latter inside `HandleMessage`, adjacent to WM_DESTROY handling and a `msg==0x218/wParam==0x12` branch that sets global byte 0x6CD788=1).

### 3.4 Semantics
**cmd 04 1C = parameterless keyboard-only control/refresh pulse.** Fired whenever a global app/window state flag is toggled on for a keyboard-type device view. It carries no data (all param bytes zero) and only a status byte comes back. Most plausible meanings: "enter/refresh config mode", "re-activate on-board config" or "apply pending state" — it is *not* part of any of the table transfer flows documented here (those always run inside cmd 01…cmd 02 sessions). A driver port should send `04 1C 00 1C 00…` and expect `recv[7] ∉ {0xFF,0xFE}`; its exact device effect should be verified by observing LED/config state changes on hardware.

## 4. Command 0x15 — chunked WRITE of the macro definition table — builder 0x47D8E0

### 4.1 Signature (thiscall, `ret 8`)
```c
int write_macro_table(void* this,
                      u8* src,        // [ebp+8]  table image
                      u32 total_len); // [ebp+0xc] total bytes to write
```

### 4.2 Construction
```
memset(buf,0,0x40); buf[0]=0x04; buf[3]=0x15; buf[7]=0
loop (off = 0; off < total_len; off += this->byte[0x658]):    // NO page arg, offset starts at 0
  chunk = min(this->byte[0x658], total_len - off)             ; 56 or 24
  buf[4] = (u8)chunk
  buf[5] = off & 0xFF ; buf[6] = off >> 8                     ; LE16 offset within the table
  memcpy(&buf[8], src + off, chunk)
  checksum buf[3..63] → buf[1..2]
  0x4788B0(this+0x60C); 0x47BD30(...); unlock                 ; LOCK A
  recv[7] checks; return rc / -102 / -103 on error
return 1
```
**Wire:** `04 <cksum> 15 38 00 00 00 <56B>` , `04 <cksum> 15 38 38 00 00 <…>`, …

### 4.3 Response
Status byte only — no payload consumed.

### 4.4 Callers
| call site | function | class | notes |
|-----------|----------|-------|-------|
| 0x497234 | 0x4966C0 (vtable 0x69AD20, slot 167) | keyboard | main macro apply |
| 0x4AA90F / 0x4AAA04 | 0x4A9B60 (vtable 0x69B134) | mouse | mouse variant (two `[0xEC8]`/cmd-AA branches) |

### 4.5 The table image built by 0x4966C0 ("apply macro.config")
Sources: config file **`macro.config`** (`0x693A44`/`0x695CC0`), per-macro UI controls **`MacroInfo`**, **`Guid`**, **`Events`**, macro files **`.mac`** (all strings verified in `.rdata`).
```c
n = argList.size();                                   // number of macro entries
total = n*2 /*offset array*/ + n*4 /*per-entry hdr*/  + Σ_i count_i*4 /*events*/ + 0x10 /*hdr*/;
if (this->[0x890]) cmd_03_read_info(dev, this+0x1534);        // refresh info
capacity = this->[0x153A] << 7;                                // info[6] * 128 bytes
if (total > capacity) return (total - capacity)/4 + 1;         // "overflow by N events" error
buf = malloc(total);
// -- 16-byte header --
buf[0..1] = 0x55AA;                // magic, LE
buf[2..3] = (u16)total;            // total table length
buf[4..5] = (u16)n;                // entry count
buf[6..15] = (not initialized by the app — heap contents)
// -- offset array at +0x10 --
for (i = 0; i < n; i++) {
    *(u16*)(buf+0x10 + i*2) = cursor;                 // absolute offset of entry i's records
    // -- per-entry records at cursor --
    count_i = _wtoi(GetText("Events", i));            // event count from UI
    *(u16*)(buf+cursor) = count_i;  buf[cursor+2..3] = (not initialized);
    cursor += 4;
    for (j = 0; j < count_i; j++) {
        u32 ev = parse(GetText("Events", i, j));      // 0x4BCAD0/0x44ECD0 text→u32
        *(u32*)(buf+cursor + j*4) = ev;               // 4-byte event record
    }
    cursor += count_i*4;
}
cmd_01_begin(dev); rc = cmd_0x15(dev, buf, total); free(buf); cmd_02_end(dev, 1);
```
**Table layout (wire):**
```
+0x00  u16 0x55AA          magic
+0x02  u16 total_len
+0x04  u16 entry_count N
+0x06  10 bytes reserved (uninitialized in app)
+0x10  u16 offset[N]        absolute offsets (from table start) of each entry's record block
      per entry:  u16 event_count ; 2 bytes reserved ; event_count × u32 events
```

### 4.6 Semantics
**cmd 04 15 = "upload macro definition table to offset 0"** — a self-describing (`0x55AA` magic + length + count) macro/event table, 4 bytes per macro event. Written in `dev->byte[0x658]`-sized chunks starting at device offset 0 (the command byte itself selects the macro area; the offset field is simply the running position within this table). The 4-byte event encoding is produced by the UI text parser (`0x4BCAD0`→`0x44ECD0`) — reverse it from `macro.config`/`.mac` content for exact key/delay bitfields (next action).

## 5. Command 0x17 — chunked WRITE of the "ShootData" rapid-fire table — builder 0x47DB70

### 5.1 Signature (thiscall, `ret 8`)
```c
int write_shoot_table(void* this, u8* src /*[ebp+8]*/, u32 total_len /*[ebp+0xc]*/);
```

### 5.2 Construction — like 0x15 but with a FIXED 56-byte chunk and **NO LOCK**
```
memset(buf,0,0x40); buf[0]=0x04; buf[3]=0x17; buf[7]=0
loop (off = 0; off < total_len; off += 0x38):                  ; FIXED 0x38 (56) — ignores dev->byte[0x658]!
  chunk = min(0x38, total_len - off)
  buf[4] = (u8)chunk ; buf[5..6] = LE16(off)
  memcpy(&buf[8], src + off, chunk)
  checksum buf[3..63] → buf[1..2]
  rc = 0x47BD30(this, buf, 0x40, recv, 0x40, &n)               ; NOTE: no 0x4788B0 lock / no unlock
  recv[7] checks (-102/-103)
return 1
```
This is the **only** builder in the family that does **not** take lock A (or B) around the transaction.

### 5.3 Response
Status byte only.

### 5.4 Caller (single)
| call site | function | trigger |
|-----------|----------|---------|
| 0x4AB6C7 / 0x4AB7A0 | 0x4AAC20 | called from 0x4739E0 **only when device type (parent+0x1788) == 2 (mouse)** |

0x4AAC20 builds the same `0x55AA`-framed table as cmd 0x15, but with **N = 4 fixed entries** (`[0x6CC800] = 4` — 4 mouse buttons), sources: UI controls **`ShootData_%d`**, **`.Shoot`** files, **`Events`** counts, event values parsed from `Events` text controls (`0x695294`):
```
total = 4*2 + 4*4 + Σ count_i*4 + 0x10      (capacity check against [0x153A]<<7 as well)
header: 0x55AA | total_len | 4
offset[4] at +0x10; per entry: u16 count + 2 reserved bytes + count × u32 events
cmd_01_begin(dev) (gated by [0xEC8]/cmd-AA); rc = cmd_0x17(dev, buf, total); free; cmd_02_end(dev,1)
```

### 5.5 Semantics
**cmd 04 17 = "upload rapid-fire / 'Shoot' event table (mouse, 4 buttons)"** — same container format as the macro table, written at device offset 0 in **fixed 56-byte chunks** regardless of the negotiated chunk size, and **without** the transaction lock. Because the chunk size is hardcoded to 0x38, this command presumably targets only the 56-byte ("normal") interface mode; a driver should replicate the fixed 56-byte chunking exactly.

## 7. Suggested next actions (Linux driver port)
1. **Confirm the device-side address of the cmd-0x27 bank**: write a recognizable pattern with 04 27 (page 0), then probe with 04 05 reads across the config memory to find where it lands; also try 04 07 immediately after to see whether bank 0 changed (should not).
2. **Decode the 4-byte macro/Shoot event records**: they originate from the UI text parser (0x4BCAD0/0x44ECD0) fed by `macro.config` / `.mac` / `.Shoot` files in `DefaultData/` — correlate a stored file with the same table captured on the wire to recover key-code/delay bitfields.
3. **Probe cmd 0x1C on hardware**: send `04 1C 00 1C 00 00 00 00` and watch LED/config state (candidate meanings: enter/refresh config mode, re-apply on-board state). Also test it on a mouse — the app only ever sends it to keyboards (type 1).
4. **Verify the `page*512` addressing of cmd 0x09/0x27** with page > 0 (the app forbids it client-side; the firmware may still accept it — that would give access to additional banks, possibly the layer pages of [R2]).
5. Note the two quirks a compatible driver must reproduce: cmd 0x17's **fixed 56-byte chunk** and its **missing transaction lock**; and cmds 0x09/0x27 deriving their length from a **previously set `dev->word[0]`** (set by 0x47F440 during the init read) rather than from an argument.
6. The 16-byte header bytes `[6..15]` and the per-entry bytes `[+2..+3]` of the 0x55AA tables are **not initialized by the app** (raw heap). Capture real traffic to learn whether the firmware ignores them or the heap happens to be zero — a driver should zero them for determinism.
